# План этапов работ

## Этап 1 — Стабильность текущего продукта (сделано в репозитории)

- [x] Windows: `setup_windows.bat`, `START_BOT.bat`, `STOP_BOT.bat`, `requirements.txt`, шаблон `telegram_bot/config.example.py`, проверка `config.py` в `run_bot.py`. Инструкция: [WINDOWS-ZAPUSK.md](WINDOWS-ZAPUSK.md).
- [x] Исправить ответ API при истёкшей сессии (JSON 401 вместо HTML-редиректа) — загрузка фото в админке.
- [x] Надёжный `fetch` для загрузки фото: проверка `Content-Type`, сообщения об ошибках, лимит размера.
- [x] Пути к боту через `BOT_DIR` / автоопределение рядом с `dashboard/`, fallback `/opt/bot/telegram_bot`.
- [x] Лимит тела запроса (`MAX_CONTENT_LENGTH`), обработка слишком больших файлов.
- [x] Корректное отображение статуса/логов без systemd (Windows / локальная разработка).

## Этап 2 — Продакшен на сервере

- [ ] Nginx (или Caddy) перед Flask: HTTPS (Let's Encrypt), прокси на `127.0.0.1:8080`.
- [ ] Переменные окружения: `FLASK_SECRET_KEY`, `DASHBOARD_PASSWORD`, `SESSION_COOKIE_SECURE=1` при HTTPS.
- [ ] systemd: юниты `perfectorganic-bot` и `perfectorganic-dashboard`, `Restart=always`, лимиты памяти при необходимости.
- [ ] Резервное копирование `saved_posts.json`, `posted_ids.json`, `custom_prompts.json`.

## Этап 3 — Подготовка к продаже и нескольким клиентам

- [ ] Убрать один общий пароль: либо отдельные логины, либо OAuth2 / SSO (зависит от модели продаж).
- [ ] Шаблон `config.py` / документация по выдаче `BOT_TOKEN`, ключей Groq/Together без попадания в git.
- [ ] Docker Compose (опционально): бот + дашборд + nginx для предсказуемого деплоя у покупателя.
- [ ] Юридическое: оферта, лимиты ответственности, обработка персональных данных (если собираете).

## Этап 4 — Масштаб (несколько ботов / тенанты)

- [ ] Отдельные инстансы на поддоменах или префиксах с изоляцией данных и конфигов.
- [ ] Централизованный мониторинг (uptime, алерты в Telegram владельцу).

Подробности по симптомам «бот остановлен» и «небезопасное соединение» — в [TECH-NOTES.md](TECH-NOTES.md).
