# Техническая справка

## Почему не загружалось фото в админ-панели

Частая причина: **сессия Flask истекла**, а защищённые маршруты `/api/*` при отсутствии `logged_in` отдавали **редирект на HTML-страницу логина**. Скрипт делал `response.json()` и получал не JSON — ошибка или «тишина» в интерфейсе.

**Исправление:** для путей `/api/` при неавторизованном доступе возвращается `401` и JSON `{"ok": false, "error": "..."}`. На фронте проверяется `Content-Type` и показывается понятное сообщение.

Дополнительно проверяйте: не блокирует ли **nginx** тело запроса (`client_max_body_size`), достаточно ли места на диске, не обрывается ли соединение по таймауту прокси.

## Почему соединение «небезопасное» на текущем порту

Если админка открыта как `http://IP:8080`, браузер честно показывает **HTTP без шифрования**. Это нормально для внутренней сети и не означает «сломанный» бот.

Для **публичного доступа** (интернет, продажа клиентам):

1. Поднять **HTTPS** (Let's Encrypt) через **Nginx** / **Caddy** как reverse proxy к Flask.
2. Включить `SESSION_COOKIE_SECURE=1` в окружении, чтобы cookie сессии не уходили по открытому HTTP.

## Нужен ли домен, чтобы бот не «падал»

- Бот с **long polling** (`run_polling()`), как в этом проекте, **не зависит от домена**. Стабильность определяется токеном, сетью, процессом на сервере и лимитами Telegram API.
- **Домен + HTTPS** нужны, если перейдёте на **webhook** (Telegram шлёт запросы на ваш URL) или если хотите **удобную и доверенную** админку для клиентов.

Падения чаще связаны с: необработанными исключениями, нехваткой памяти, остановкой systemd, конфликтом второго экземпляра с тем же токеном, сетевыми таймаутами (в коде уже смягчены для `TimedOut` / `NetworkError`).

## Переменные окружения дашборда

См. `dashboard/env.example`. Критично для продажи: не хранить реальные пароли и секреты в коде — только в env или секрет-хранилище.

## Рекомендации по стабильности и продаже

1. **Один токен — один процесс** бота; мониторинг `systemctl status` и автоперезапуск.
2. **Секреты** вне git (`config.py` уже в `.gitignore` — правильно).
3. **HTTPS** для админки в продакшене; сильный `FLASK_SECRET_KEY`.
4. Для **нескольких клиентов** — изоляция: отдельный VPS/контейнер или чёткое разделение конфигов и данных (пока архитектура «один бот — одна панель»).
5. **Бэкапы** JSON с постами и статистикой перед обновлениями (`git pull` + копирование дашборда на сервере).
